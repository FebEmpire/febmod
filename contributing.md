# Contributing to FebMod

Thank you for your interest in contributing to FebMod! We welcome contributions from developers, testers, documentation writers, and community members.

## Before You Start

Please:

- Read the project README and existing documentation.
- Search existing issues before creating a new one.
- Check if a similar pull request already exists.
- Be respectful and constructive in all interactions.

## Reporting Bugs

When reporting a bug, please include:

- A clear and descriptive title.
- Steps to reproduce the issue.
- Expected behavior.
- Actual behavior.
- Screenshots or logs (if applicable).
- Operating system, version, and environment details.

Use the GitHub Issues page to submit bug reports.

## Suggesting Features

Feature requests are welcome.

Please provide:

- A clear description of the proposed feature.
- The problem it solves.
- Potential use cases.
- Possible implementation ideas (optional).

## Development Workflow

1. Fork the repository.
2. Create a new branch:

```bash
git checkout -b feature/my-feature
```

or

```bash
git checkout -b fix/my-bugfix
```

3. Make your changes.
4. Test your changes thoroughly.
5. Commit using clear commit messages.
6. Push your branch to your fork.
7. Open a Pull Request.

## Commit Message Guidelines

Use meaningful commit messages:

```text
feat: add support for custom modules
fix: resolve crash when loading configuration
docs: update installation instructions
refactor: simplify validation logic
```

## Pull Request Guidelines

Before submitting a Pull Request:

- Ensure the project builds successfully.
- Run all tests.
- Update documentation when necessary.
- Keep changes focused and related to a single topic.
- Link related issues when applicable.

### Pull Request Template

Include:

- Summary of changes
- Motivation
- Testing performed
- Related issue(s)

## Code Style

Please follow the existing coding style used throughout the project.

General recommendations:

- Write clean and readable code.
- Use descriptive names.
- Keep functions focused and maintainable.
- Add comments only when necessary.
- Avoid unnecessary dependencies.

## Documentation Contributions

Documentation improvements are highly appreciated.

Examples include:

- Fixing typos
- Improving explanations
- Adding examples
- Updating outdated information

## Community Standards

By participating in this project, you agree to:

- Be respectful and professional.
- Welcome constructive feedback.
- Help create an inclusive environment.
- Avoid harassment, discrimination, or abusive behavior.

## Questions

If you need help, open a discussion or create an issue and a maintainer will assist when available.
